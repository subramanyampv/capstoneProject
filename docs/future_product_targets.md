### U1 design boundaries

Current memory retains an allowlisted projection rather than full graph state (`src/capstone_agent/support/memory.py:154-194`); process-local scope is visible at `support/runtime.py:18`. Externalizing full graph checkpoints would reintroduce a privacy risk that earlier projection work deliberately removed. Persisting only “latest” is insufficient if historical versions/writes/blobs/backups still retain prohibited data. Opaque references can still be linkable and need tenant isolation, retention and deletion policy.

PostgreSQL and Redis are alternatives with different operating choices, not a requirement to combine cache plus database. A deployment decision must specify recovery point, expiry/eviction, conflict/locking behavior and outage policy. Shared preferences and mock tickets currently use different local stores; moving only memory cannot claim horizontal readiness. First define identity, deduplication and session concurrency, then evaluate one backend in an isolated future branch. No backend/provider dependency is installed now.

### U2 correctness before concurrency

`ToolContext` owns mutable calls, triggers, categories, records, facts and evidence (`support/registry.py:20-33`); registry reserves the eighth call for escalation (`:106-108`) and admits evidence only after validated completion (`:127-128`). Parallelizing the existing methods without redesigning reservation and merge ownership could overspend the budget, race on categories/triggers, misorder facts, or compose before mandatory evidence is ready. A lock around embeddings limits resource overlap but does not independently prove bounded executor queues or cancellation of timed-out work (`:126`; `scripts/run_final_suite.py:55-67`).

Order lookup must establish authorized order/category before corresponding eligibility or category-bound policy lookup. Product information, policy retrieval and tracking are independent only when their exact inputs are already established; “different tool names” is not sufficient. Keep writes serialized and escalation based on the final code-owned trigger set. Define whether sibling reads finish, cancel or are discarded after failure; do not admit late facts. A future measured performance improvement must not hide missing required answers behind averages or relabel timeouts as correct answers.

### U3 privacy and authority before detector coverage

Use an explicit raw invocation value and a separate normalized security view with consistent interpretation across guard/entity/intent stages. Do not log either. Existing exact configured-secret removal has to remain effective if normalization changes the view of a secret; test raw and normalized forms under the same privacy boundary. Avoid normalization-induced reference substitution across customers and unintended command changes. Removing every format character indiscriminately is a proposed rule that needs validation, not a universal security correction.

A model detector must be fine-tuned/evaluated for injection and pinned with its tokenizer, ONNX graph, conversion/opset/runtime and license. Decide truncation/chunking behavior, including attacks beyond a token limit, and treat corpus/tool content as separate attack surfaces. Keep false alarms visible: legitimate quoted unsafe requests, multilingual text and return/privacy refusals should not automatically lose service. On a detector crash/unavailable model, preserve deterministic enforcement and use a declared safe fallback; never silently declare input safe. No measured detector quality or latency is asserted here.

### U4 minimization before transport

Existing minimized telemetry is a boundary worth preserving (`support/runtime.py:20-32`; `observability/support_tracing.py:14-42`). Define safe span names, low-cardinality status/error codes, duration, tool name, policy/build version and approved random correlation IDs. Explicitly forbid content in attributes, events, baggage, URLs, exception messages and resource labels. Configure egress credentials outside the artifact and avoid tenant/customer identifiers as trace tags.

OTLP/Collector/backend transport adds storage, authentication, retention and outage behavior. Regex processors are useful secondary defense but cannot establish universal PII absence. Test emitted payloads with SDK behavior as well as application dictionaries: auto-instrumentation may add content. Keep existing LLM evaluation tracing only where useful; do not duplicate spans or leak bodies through a second exporter. Sampling is not a privacy control.

## Escalation rule and implementation boundary

No task above is an instruction to implement now. If a new current-build failure is found, record exact input/output/build and file:line evidence, explain the affected promised behavior, and isolate the smallest repair. Classify by impact, not by an audit's “critical” label or the user's proposal number. Preserve evidence and revalidate changed source; do not hide failure by modifying expectations or replacing a primary score. A proposed production exploit, LOC count, lack of CI, slow correct answer or monolithic function alone is not a P1 finding.

Already measured limitations remain candid: ticket readback does not validate packet digest; current digest strings may be redacted; default human calibration cannot establish authorship; anchored AI proxy review is not actual human validation; same-parser replay is not independent semantics. Narrow claims or require genuine evidence rather than implement broad infrastructure to make them sound stronger.
