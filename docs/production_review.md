# First production review — deferred until core acceptance

Current consolidated decisions, complete finding matrices and versioned tasks: [Future product targets and review addendum](future_product_targets.md). User proposal numbers are not P1 severity; no infrastructure/performance implementation is scheduled in the active correctness evaluation.

User direction: fix the existing refund-intent and privacy-routing defects before adding infrastructure or features. The first holdout remains failed evidence (8/10 hard/all checks). A separately authored replacement set is frozen and kept blind while a new candidate is repaired. None of the four production extensions below is implemented by this discussion.

| Review item | Recommended design | Required evidence before adoption |
|---|---|---|
| Distributed state | Prefer Postgres for a multi-instance deployment. Persist only the bounded retained projection; give tickets/preferences a shared authoritative store too. Define session concurrency, identity/tenant scope, idempotency, pooling, migrations, reset/TTL deletion and backup retention. A checkpointer replacement alone is insufficient for horizontal scaling. | Process restart and replica handoff preserve allowed context; concurrent turns cannot cross tenants or duplicate tickets; reset removes all retained checkpoint versions/writes/blobs. [LangGraph persistence](https://docs.langchain.com/oss/python/langgraph/persistence), [PostgresSaver](https://reference.langchain.com/python/langgraph.checkpoint.postgres/PostgresSaver) |
| Parallel dispatch | Run independent reads concurrently using graph branches/reducers or bounded async calls. Preserve order/category-dependent policy selection, atomic budgets, current-turn evidence merging and deterministic safety precedence; serialize writes. | Compare the same cases, provider settings and load against sequential control; report p50/p95, error rates and token/call counts. The suggested 40% p95 reduction is an unmeasured hypothesis, not a project result. [Graph API](https://docs.langchain.com/oss/python/langgraph/graph-api) |
| Guard-In preprocessing/classifier | Consider a deterministic normalized security view (NFKC, explicitly handled format/zero-width characters) shared by guard/entity/intent interpretation. Test false positives, confusables, expansion limits and reset/command behavior. Evaluate a separately fine-tuned injection detector and ONNX conversion on representative local cases. | Plain DeBERTa-v3-small is a pretrained model, not an off-the-shelf injection classifier. Benchmark calibrated false negatives/positives and CPU tail latency; model risk scores cannot grant authorization or clear deterministic flags. Ordinary paraphrase defects still require independent obligations. [Microsoft model card](https://huggingface.co/microsoft/deberta-v3-small), [example fine-tuned detector](https://huggingface.co/protectai/deberta-v3-base-prompt-injection-v2) |
| OpenTelemetry | Common span/trace identifiers and OTLP Collector export to a chosen backend; retain LangSmith for LLM-specific evaluation if useful. Exclude user/tool/prompt content at instrumentation, then use allowlists/redaction in the Collector. Avoid duplicate instrumentation/spans. | Cross-node parent/correlation verification, canary checks, exporter failure isolation and bounded queues. Collector redaction is a second safeguard; do not export raw content merely because a downstream processor is configured. [OTel sensitive data](https://opentelemetry.io/docs/security/handling-sensitive-data/) |

For this local capstone, the implementation order is core correctness and independent validation first; then consider guard hardening, measured parallel reads, durable state when multi-instance deployment is required, and common telemetry. Actual Kubernetes deployment changes those priorities and requires a separately scoped operational design. Knowledge graphs and external commerce/weather integrations remain deferred.
