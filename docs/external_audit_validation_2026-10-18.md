## Corrections to broader audit claims

1. **Scores are judgments, not measurements.** The 6.0 overall architecture score has no stated calibrated weighting or benchmark and should not become an acceptance threshold. LOC, regex count and graph size do not quantify correctness or generalization.
2. **Import success does not prove zero cycles.** Python can import cyclic modules successfully. A lightweight AST check here found no cycles among literal absolute intra-package module imports, including imports inside functions. It does not resolve dynamic imports, relative imports or every `from package import submodule` edge; no complete dynamic dependency proof is claimed. “48 local imports” depends on counting nested syntax: our conservative immediate-function-body count was 41 and is not directly comparable.
3. **Test/LOC numbers are historical and definitions matter.** Current static inventory: 51 Python source files / 4,471 source lines, 26 `test_*.py` files, 41 Python + 6 shell scripts. The audit's 365 passing tests / 22.98 seconds belong to its prior run, not an independently measured current result. This review deliberately did not collect/run tests while evaluation is active. The audit's no-coverage statement was not independently exhaustively established.
4. **Full retrieval verification is startup/construction work for shared handles**, not every interaction in CLI chat/UI/final suite. Retrieval still requests `chunk_count` candidates (`retrieval/chroma_store.py:122`), so corpus-scaling concerns remain without a measured latency attribution.
5. **Implicit adaptation cost can exceed the audit's claimed two embeddings.** `support/preferences.py:134-141` considers up to two prior user messages and embeds the current query and each old message within the loop: up to four calls, with early returns. This is a conditional path, not every turn. Preference rewrites perform retention/report rebuilding, not literally no behavioral work (`:61-65`).
6. **`asyncio.wait_for(to_thread(...))` is not worker cancellation.** Confirmed for reads/model (`support/registry.py:126`; `support/model.py:28`). The mock write is deliberately synchronous to prevent abandoned orphan tickets (`support/registry.py:121-124`), so this is not evidence of late unreported transactional writes. `asyncio.run` also waits for default-executor shutdown; nominal timeout is not proof of a strict end-to-end wall-clock cap. Later test slow-read return versus request completion and absence of late evidence admission.
7. **Deployment limits are declared scope.** Local SQLite/mock queues (`support/services.py:150-176`), process memory (`support/runtime.py:18`) and POSIX preference locks (`support/preferences.py:56-66`) are suitable for the synthetic single-machine project. No tracked GitHub workflow or Dockerfile was found, but absence of CI/containerization is not automatically a capstone blocker. Real identities/authorization, distributed persistence and deployment operations would be separate production work.
8. **Model agency is bounded intentionally.** Code-defined tool obligations and outcomes are safety mechanisms (`support/graph.py:224-227`, `:349-361`), not proof that the agent architecture is invalid. Refactoring must retain that authority boundary.
9. **Generalization is not established by fixture success.** Catalog noun lists, misspelling handling (`support/obligations.py:12`) and topic-specific retrieval rewrites are real; “generalizes to fixtures, not language” is a stronger empirical claim than these reads support. Authored domain constraints can be legitimate. Evaluate new catalog names, paraphrases, conflict groups and compound intents independently before claiming broader support; do not alter the unopened blind v4 to test this review.
10. **Historical evidence must remain historical.** README acceptance narrative is older (`README.md:66`); current status is explicitly centralized (`docs/current_status.md:3`). An old successful security scan, reviewed packet or run must not be presented as proof for changed source or a refreshed submission. No full credential/history scan or remote-code review was performed here; `.env` history path listing was empty, which is a limited path-based observation only.

If a command's exit status is used as an approval decision, fix its status/exit mismatch before relying on it.

**Next small maintenance increments:** calibration/probe command hygiene and frozen limit consolidation, then conflict metadata externalization and one pure outcome extraction. These need their own candidate checkpoint and targeted regression tests; they are not prerequisites demonstrated by the external audit for completing the active correctness run.

**Can wait:** performance tuning/caching, graph-wide decomposition, declarative detector migration, adapter consolidation, import cleanup, snapshot search exclusions, folder taxonomy, CI/containerization and multi-instance design. Do not sacrifice a stable evaluation candidate to a broad architectural rewrite. Correctness failures remain blockers even when the runtime is fast; correct slow answers alone do not fail correctness under the user's policy.
